# Zephus 1.0.0 — Verification Artifact

Repeatable E2E proof for the prepared stable 1.0.0 release candidate (not
published yet; this tree is package version `1.0.0` on `main`).

## Repeat

```bash
git fetch --all --prune
node build-scripts/test-all.js --skip-smoke   # unit, compile, lint, format, typecheck, syntax, config, astro-build, coverage, e2e-failures
xvfb-run -a npm run smoke:runtime:fast        # real Electron E2E: save, drafts, publish, git, external-change
npm run test:e2e:all                          # mock-website failure battery across all 10 themes + mutated astro rebuilds
```

Linux headless needs `xvfb`. First Electron launch in a fresh container needs the
sandbox helper fixed once:

```bash
sudo chown root:root node_modules/electron/dist/chrome-sandbox
sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
```

## Results (2026-11-18, round-5 asset/Git integrity audit on 1e9ef01)

Branch `next-1.0.0` at `1e9ef01a34f65de44c109301bcfba80a33d81081` plus
this batch's working-tree edits. The asset audit found that an imported legal
name such as `hero #100%.png` returned an unencoded web path: the browser read
`#100%.png` as a fragment and requested a different file. Imported, listed, and
renamed asset URLs now encode each segment while preserving the original disk
and display name. Read/delete/rename decode candidates separately, prefer normal
URL semantics, fall back to safe raw paths for legacy literal-percent names,
and hard-reject encoded traversal/slashes before lexical and realpath checks.
The all-theme E2E battery now proves spaces, `#`, `%`, list/read/rename
round-trips, raw legacy references, and traversal refusal through real main
services.

The renderer Git audit found a cross-project async race: a slow status, commit,
push, pull, init, or pull refresh could publish into a newly opened project.
Every Git outcome now checks the originating project path before changing the
panel, status text, pull completion flow, or follow-up refresh; the underlying
Git operation still completes, but stale UI publication is abandoned.

Correction (round 3): the paragraph above overstated a limitation. Deep
verification found that no parser, command, or renderer ever populates
`BlockNode.children` — every block is a top-level child of its section
(`SectionNode.children: BlockNode[]`), and a `columns` block carries its cell

divs (`src/shared/blockRender.ts:395-406`). Arrow traversal therefore covers
the complete document order; there are no nested blocks to miss. The vestigial
optional `BlockNode.children` field remains only for defensive cloning and
sidecar tolerance.
